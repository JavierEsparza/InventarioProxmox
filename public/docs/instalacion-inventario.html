1. Alcance de la aplicación

El inventario centraliza información operativa de infraestructura Proxmox y permite mantener una vista histórica y auditable.

Inventario

Clusters, nodos, máquinas virtuales, interfaces, direcciones IP, storage, hardware y estado de agentes.

Sincronización

Actualización desde Proxmox API, procesos diarios y flujos SSH para datos complementarios.

Auditoría

Revisión de hosts mediante SSH/Infransible, estado de servicios, HA, VIP/Keepalived y conectividad.

PBS

Gestión y sincronización de servidores, datastores, snapshots, tareas y respaldos de Proxmox Backup Server.

2. Requisitos previos

  • PHP 8.1 o superior con extensiones requeridas por Laravel y el driver de base de datos.
  • Composer 2.
  • MySQL o MariaDB para producción.
  • Node.js y npm para compilar los assets frontend.
  • Acceso de red desde el servidor web hacia las APIs Proxmox/PBS y los equipos auditados por SSH.
  • Usuario de sistema con permisos de escritura sobre storage/ y bootstrap/cache/.
  • Repositorio: git@github.com:JavierEsparza/InventarioProxmox.git.
Importante: el archivo .env real nunca debe publicarse en Git. Esta guía sólo documenta nombres y valores de ejemplo.

3. Instalación paso a paso

  1. Obtener el código.
    git clone git@github.com:JavierEsparza/InventarioProxmox.git
cd InventarioProxmox
  2. Instalar dependencias PHP.
    composer install --no-interaction --prefer-dist
  3. Crear el entorno local.
    cp .env.example .env
php artisan key:generate
  4. Editar la configuración. Completar base de datos, URL, ambiente, credenciales SSH y parámetros de logging en .env. Ver la tabla completa en la sección siguiente.
  5. Instalar y compilar frontend.
    npm ci
npm run build
  6. Crear estructura de datos.
    php artisan migrate --seed
php artisan storage:link
php artisan optimize:clear
  7. Probar en desarrollo.
    php artisan serve
npm run dev

En producción, configurar el virtual host para apuntar exclusivamente a public/; no publicar la raíz del repositorio.

5. Configurar Proxmox y PBS

  1. Crear la base de datos y ejecutar las migraciones.
  2. Ingresar a la aplicación con un usuario autorizado.
  3. Registrar los clusters y credenciales de Proxmox desde el módulo correspondiente.
  4. Configurar los servidores PBS y sus parámetros desde el módulo PBS.
  5. Validar que el servidor web tenga conectividad a las APIs y que los certificados/puertos sean accesibles.
  6. Ejecutar una sincronización controlada y revisar storage/logs/proxmox-sync.log.
Nota: las conexiones de Proxmox y PBS se administran desde la aplicación y se persisten en la base de datos. No se deben hardcodear tokens, contraseñas ni URLs privadas en el código.

6. Migraciones y datos iniciales

# Crear estructura y datos iniciales
php artisan migrate --seed

# Si la aplicación ya tiene datos, revisar primero el plan de migraciones
php artisan migrate:status

# Limpiar configuración/cache luego de cambiar .env
php artisan optimize:clear

Los seeders incluyen permisos y datos iniciales. Revisarlos antes de ejecutarlos en una base existente.

7. Comandos operativos

ComandoFunción
php artisan proxmox:sync-dailyEjecuta la sincronización diaria del inventario Proxmox.
php artisan pbs:sync-allSincroniza todos los servidores PBS configurados.
php artisan pbs:sync-all --server=ID_O_NOMBRESincroniza un servidor PBS específico.
php artisan qemu:refresh-qga-ip-osActualiza IP, sistema operativo y estado del QEMU Guest Agent.
php artisan qemu:refresh-qga-ip-os --limit=100Limita la cantidad de VM procesadas.
php artisan qemu:import-ip-os-pdf archivo.csv --dry-runImporta comparación de IP/OS sin modificar datos.
php artisan proxmox:import-ips archivo.csvImporta direcciones IP desde CSV.
Precaución: los comandos de sincronización e importación pueden modificar datos. Ejecutar primero con alcance controlado y revisar logs.

8. Puesta en producción

git pull --ff-only origin main
composer install --no-interaction --prefer-dist
npm ci
npm run build
php artisan migrate --force
php artisan optimize:clear
php artisan config:cache
php artisan route:cache
php artisan view:cache
  • El document root del virtual host debe ser /ruta/al/proyecto/public.
  • El usuario del servidor web debe escribir en storage/ y bootstrap/cache/.
  • Usar APP_DEBUG=false.
  • Programar proxmox:sync-daily según la ventana operativa.
  • Configurar workers sólo si se cambia QUEUE_CONNECTION desde sync.
  • No ejecutar comandos de cache como root si luego la aplicación corre con otro usuario.

9. Checklist de validación

php artisan about
php artisan route:list
php artisan migrate:status
php artisan test
php -l app/Http/Controllers/ProxmoxController.php
composer validate --no-check-publish
  • La URL responde desde el navegador.
  • Login y permisos funcionan.
  • La conexión a la base está operativa.
  • Las migraciones están aplicadas.
  • Los clusters aparecen en el inventario.
  • La sincronización registra resultado y duración.
  • Los logs no contienen credenciales.
  • Los assets CSS/JS cargan correctamente.
  • Las auditorías SSH alcanzan los hosts esperados.
  • PBS muestra servidores y tareas configuradas.

10. Seguridad y archivos excluidos

  • No publicar .env, contraseñas, tokens, claves privadas ni cadenas de conexión.
  • No incluir vendor/, node_modules/, logs, sesiones, cache ni archivos generados.
  • No incluir backups *.bak*, *.bkp* o carpetas de respaldo.
  • Los valores de VITE_* terminan en el frontend: nunca deben contener secretos.
  • Las credenciales de Proxmox/PBS se mantienen en la base administrada por la aplicación.
  • Revisar cambios con Git antes de publicar.
